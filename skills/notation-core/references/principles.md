# principles — 記法中心設計の原則（詳細）

[SKILL.md](../SKILL.md) で要約した原則の「なぜ」と「どう適用するか」を展開する。具体的な文法は持たず、どの記法にも当てはまる土台を述べる。

---

## 原則 1: 意味とレイアウトを分ける

**主張。** 「何があり、何に依存するか（意味）」と「画面のどこに、どんな順で置くか（レイアウト）」は、別のセクションに分けて保持する。

**なぜ。** 両者を混ぜると、見た目を変えるたびに意味が汚れ、意味を変えるたびに見た目を作り直すことになる。分けておけば、

- 意味だけを差分レビューできる（依存が 1 本増えた、を 1 行で読める）。
- レイアウトは省略可能にできる。無ければ描画側が決定的に自動配置すればよい（原則 5）。
- 同じ意味を、別のレイアウトや別の出力（HTML / Mermaid）で何度でも描き直せる。

**適用。** DSL には「意味セクション」と「レイアウトセクション」を物理的に分けて置く。レイアウトセクションには座標やランクなどの**位置情報だけ**を入れ、意味的な属性（種別・依存）は決して入れない。レイアウト行に意味が漏れたら、それは設計のバグである。

---

## 原則 2: 1 行 1 意味単位、行頭に種別キーワード

**主張。** 記法は行指向にし、1 行で 1 つの意味単位（ノード 1 つ、エッジ 1 つ）を表す。各行の先頭に「これは何の行か」を示す型（id や種別）を置く。

**なぜ。**

- **差分が素直になる。** 1 要素 1 行なら、変更が行単位の diff として読め、レビューも機械的マージも安定する。
- **パースが単純になる。** 行を読んで先頭トークンで分岐するだけで済み、文法が小さくなる。文法が小さいほど AI も人も間違えにくい。
- **部分読みできる。** 行頭に型があると、全体を読まずとも「package の行だけ拾う」といった走査ができる。

**適用。** ネストや多階層インデントで構造を表現しない。階層は「行の種別」と「行どうしの関係（エッジ）」で表す。インデントは「セクションの内側」を示す 1 段階だけに留め、深さで意味を持たせない。

---

## 原則 3: 全量置換をデフォルトに、巨大時はスコープ＋深度で割る

**主張。** 状態の受け渡しは、毎回**まるごと出す（全量置換）**のを既定とする。対象が大きすぎて全量が現実的でないときだけ、**スコープ（どの範囲か）**と**深度（どの粒度まで）**の 2 軸で切り出す。

**なぜ。** 差分指示（「3 行目を消して」式）は、対象の現在状態に強く依存し、AI が現在状態を取り違えると壊れる。全量なら、返ってきたテキストがそのまま新しい正本になり、取り違えが起きない。一方で、全量が大きすぎると今度はコンテキストに載らない・読めない。そこで**全体を一度に描こうとせず、範囲と粒度で小さく保つ**。

**適用。**

- まず粗い深度（システム全体や上位パッケージだけ）で全量を出す。
- 「ここを詳しく」と言われたら、**スコープを狭め**（root を下げ）、その範囲だけを**深い深度**で全量出力する。
- 「大きいから差分にしよう」ではなく「大きいから範囲を絞ろう」と考える。地図は広げるのではなく、畳んで切り出す。

---

## 原則 4: レンダラーは DSL だけを読む（自由描画の禁止）

**主張。** 描画側は、入力された DSL 以外の情報源から図を補ってはならない。自然言語の要望、口頭のレイアウト指示、元データ（リポジトリ）の再走査——いずれも描画の入力にしない。

**なぜ。**

- **正本を一本化するため。** 描画が DSL 以外を参照した瞬間、「絵に映っているが DSL に無い情報」が生まれ、DSL はもう正本でなくなる。
- **決定性のため（原則 5）。** 入力を DSL だけに限れば、出力は DSL の関数になり、再現可能になる。
- **責務分離のため。** 「何を描くか」は生成側（`repo-map-notation`）の責任、「どう描くか」は描画側（`notation-render`）の責任。描画側が中身を補完し始めると、両者の境界が溶ける。

**適用。** DSL に情報が足りないと感じたら、描画側は**推測で埋めず**、生成側に差し戻す。これは `notation-render` の中核制約として、その SKILL.md と references で**二重に明記**する。→ [notation-render/SKILL.md](../../notation-render/SKILL.md)

---

## 原則 5: 決定的であること

**主張。** 同じ DSL からは、いつ・誰が描いても**同じ図**が出る。

**なぜ。** 決定的でなければ、図の差分は「意味が変わったから」なのか「たまたまレイアウトがブレたから」なのか区別できず、地図としての信頼を失う。決定的なら、図の変化は意味の変化とだけ対応する。

**適用。**

- レイアウトに**乱数や実行時刻**を持ち込まない。
- 並び順を決める比較に**完全な全順序**を与える（最後の決め手は「DSL に書かれた順」のような安定したタイブレーク）。
- ヒューリスティックを使うなら、その手順自体を固定し、文書化する（「だいたい良い感じに」を排除する）。

---

## 原則 6: ID は安定させる

**主張。** 各意味単位には、**安定した ID** を与える。理想は対象から機械的に導ける ID（パス由来の slug など）。

**なぜ。** ID が安定していれば、対象が少し変わっても同じものは同じ ID を保ち、地図の再生成で差分が最小になる。ラベル（人間向けの表示名）は変わってよいが、ID は同一性の鍵として固定する。

**適用。** ID はラベルと分離する。ID は機械可読な文字集合に限り、空白や曖昧な記号を含めない。導出ルール（例: パスの区切りを置換して slug 化）を決めておけば、同じ対象から毎回同じ ID が出る。

---

## まとめ

これらの原則は互いに支え合う。意味とレイアウトを分ける（1）から省略可能になり、決定的自動配置（5）が効く。行指向（2）と安定 ID（6）が差分を素直にし、全量置換（3）を現実的にする。そして描画を DSL だけに閉じる（4）ことで、正本が一本化され、決定性（5）が保たれる。1 つでも崩すと、地図は「読めない絵」に逆戻りする。
