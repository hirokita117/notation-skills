# layout-algorithm — 決定的レイアウト

`@layout` が無い／部分的なときに座標を決める手順を定める。目的は唯一、**同じ `RepoMap` から常に同じ幾何（座標・並び）を出すこと**。図の見た目を固定するテーマ定数（kind ごとの色・フォント）は [theme.md](theme.md) が正本。内部モデルは [grammar.md §4](../../repo-map-notation/references/grammar.md)。

レイアウトは「上から下へのレイヤー配置（top-down）」: ランク = 縦の帯、帯内の位置 = 横の順。**以下のあらゆる並び替えは安定ソートで、最後のタイブレークは正準順（ノードのソース順 / エッジの `index`）**。これが自由度をすべて消す。

---

## 1. `@layout` の上書き意味

```
layout-line = id  ( rank=<int> | group=<str> ) ...
```

- `rank=<int>`（負可）: そのノードのランクを固定し、自動算出を上書きする。
- `group=<str>`: 名前付きクラスタに割り当てる。
- ノードは rank のみ・group のみ・両方を指定可。`@layout` に無いノードは自動ランク（§2）と既定グループ `""`。
- `@layout` は位置のみ。意味は持たない（[grammar.md](../../repo-map-notation/references/grammar.md) の E-LAYOUTSEM）。

---

## 2. ランク割り当て

目標: 「親・上流」を上に、「子・下流」を下に。

1. **ランクグラフを作る。** ランク決定には**階層系エッジ**（`contains` / `deploys` / `owns`）だけを使い、`from → to` を「from が to の上」とみなす。**依存系**（`imports` / `calls` / `reads`）は描くがランクには効かせない（相互 import などの循環があっても並びがブレないため）。
2. **階層系の循環を決定的に断つ。** 階層系に閉路（W-CYCLE）があれば、`edge.index` 昇順に辺を処理し、追加すると閉路を閉じる辺を落として非循環化する（index 順の決定的フィードバックアーク除去）。落とした辺も**描画はする**（ランクを縛らないだけ）。
3. **始点からの最長路でランクを付ける。** *始点* = 非循環化後に入ってくる階層系辺を持たないノード（ランク 0）。各ノードに「いずれかの始点からの**最長路長**」を割り当てる（1 階層ホップごとに +1）。最短ではなく**最長**を使うのは、親を必ず全子孫より厳密に上に置くため。
4. **明示の上書きを適用する。** `@layout` に `rank=` があるノードは、その値で計算値を置き換える（帯の隙間や並べ替えが生じても、作者の指定を逐語的に尊重する）。
5. **孤立・依存のみのノード。** 階層系辺に触れず `rank=` 上書きも無いノードは、`edges` を index 順に 1 パスで走査し「自分を指す依存元のランクの最大 + 1」を割り当てる（無ければランク 0）。これで外部 API や datastore が、それを読む側のすぐ下の帯に収まり、浮かない。

以上で全ノードに整数ランクが付く。

---

## 3. 帯の中のグルーピング

group はノードを横にクラスタするが、ランクは変えない。

- **グループ順を決める。** 空でない group 名を集め、Unicode コードポイント順（辞書順）で並べる。既定グループ `""` は**常に最後**（最も右）に置き、明示クラスタを先頭に出す。
- **帯内のノード順** = (グループ順の index, 次に正準ソース順)。同じランクなら、グループ A のノード群がグループ B より左に来て、各グループ内ではソース順を保つ。

（group は帯の横方向の分割であって、外接矩形を強制しない。グループごとに薄い背景を敷くのは任意で、幾何には影響しない。）

---

## 4. 座標の割り当て（固定定数）

帯の番号 = ランク。ランク *r* の帯で横スロット *s*（0 始まり、§3 の順）にあるノード *n*:

```
NODE_W = 160     （px・箱の幅、固定）
NODE_H = 48      （px・箱の高さ、固定）
H_GAP  = 40      （px・帯内の隣接箱の横間隔）
V_GAP  = 72      （px・帯どうしの縦間隔）
MARGIN = 24      （px・キャンバスの余白）

x(n) = MARGIN + s * (NODE_W + H_GAP)
y(n) = MARGIN + r * (NODE_H + V_GAP)
```

- 各帯のスロット index *s* は 0 から振り直す。帯は**左揃え**（どの帯もスロット 0 は同じ x）。最も単純で完全に決まる規則。
- キャンバス幅 = `MARGIN*2 + (最大スロット数)*(NODE_W+H_GAP) − H_GAP`、高さ = `MARGIN*2 + (最大ランク+1)*(NODE_H+V_GAP) − V_GAP`。
- **エッジの経路**: 各辺は直線。下向き（`to` が下のランク）なら `from` の下辺中央 → `to` の上辺中央。同じ帯または `to` が上（後退辺・上向き依存）なら、右辺中央 → 左辺中央。どちらを使うかは 2 つのランクだけで決まるので決定的。矢頭は `to` 端。曲線・力学シミュレーションは使わない（直線のみ）。
- **focus**: `meta.focus` のノードは focus 枠（[theme.md](theme.md) の `FOCUS_STROKE`）を付けるだけで、**幾何は変えない**（強調であって再配置ではない）。

---

## 5. 決定性（まとめ）

§2〜§4 の出力は `RepoMap` の純関数である: 反復するすべての集合に、正準ソース順で終わる明示的な全順序を与え、循環断ちは index 順の決定的 1 パス、間隔はすべて定数。よって SVG のノード位置・帯順・エッジ端点は、どのレンダラでも・何度走らせても一致する。乱数なし、幾何に時刻を入れない、ヒューリスティックのブレなし——[notation-core 原則 5](../../notation-core/references/principles.md)。
